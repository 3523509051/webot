# 微信 AGI 群聊助手 · 总览

> 本文是**现状入口**。所有描述以**当前代码的实际行为**为准，不再保留已废弃方案。
> 最后同步：2026-10-07（插件 v0.4.1）

---

## 1. 目标

一款「个人微信 AGI」：

- 登录**个人微信**（非企业微信），可被拉进群，7×24 待命
- 需要它时 **@ 它** 才出现
- 被 @ 后**短暂激活**（滑动空闲语义，见 §4），期间参与对话
- 不使用企业微信、不使用 Claw / ClawBot

> 原始目标含 **Ubuntu**，但桥为 Windows 专用，该目标**未达成**（见 §5）。

---

## 2. 现状一句话

**链路已跑通**：群里 @ 机器人 → 约 4–7 秒后回复（延迟构成见 `latency-diagnosis.md`），
窗口按「**最后一次活动后 30 秒**无动静」自动关闭（单次激活最长 120 秒）。

> ⚠️ **必须先说清的硬约束**：**桥是 Windows 专用的**。
> Ubuntu 目前只能跑 AstrBot 与插件，**无法接微信**。这是当前唯一未达成的原始目标，详见 §5。

---

## 3. 架构一览

```
┌──────────────────────── Windows（本机）────────────────────────┐
│  微信客户端 4.1.12+（必须已登录、保持运行、不锁屏）              │
│      ↑ 读：WeChatDB（本地数据库增量轮询）                       │
│      ↓ 写：WeChatGUI（UIA 优先 + OCR 兜底；rhythm=fast）        │
│  bridge/（Python 3.11 本机进程，非容器）                        │
│      ↕ OneBot v11 反向 WebSocket  ws://127.0.0.1:6199/ws        │
└───────────────────────────────┬────────────────────────────────┘
                                │
┌───────────────────────────────┴──── Docker ────────────────────┐
│  AstrBot 4.28.2                                                 │
│    · aiocqhttp 适配器（OneBot v11，监听 0.0.0.0:6199）           │
│    · 默认 LLM 管线 → DeepSeek `deepseek-flash`                  │
│    · 插件 astrbot_plugin_group_activation（v0.4.1）             │
│         ├─ @ 开关 → 滑动空闲窗口                                │
│         ├─ L1 群聊滚动背景 → 注入默认 LLM 的 system_prompt       │
│         ├─ L3 结构化长期记忆（群员画像）→ 同样注入 system_prompt  │
│         └─ [PASS] 拦截 → 让 LLM 有权「不发言」                   │
│    · 知识库：AstrBot 内置 + 本机 Ollama `bge-m3`（1024 维）      │
│    · WebUI 面板 http://localhost:6185                           │
└────────────────────────────────────────────────────────────────┘
```

**插件的边界**：不生成任何回复、不对消息内容做特殊分支；只做「开关 + 记忆 + 沉默拦截」。

## 4. 关键决策总表

| 维度 | 决策 |
|---|---|
| 编排框架 | **AstrBot**（Docker） |
| 微信接入 | **本机桥**：读微信本地数据库 + UI 自动化发送（Windows 专用） |
| 桥与框架通信 | **OneBot v11 反向 WebSocket**（解耦，桥可替换） |
| 触发方式 | **@ 即开关**；**被 @ 的那条必定回复** |
| 窗口语义 | **滑动空闲窗口**：初始 30s；每次活动（群友消息 / **机器人回复完成**）续期 30s；**回复完成时若窗口已过期则重新打开**（长回复生成可超 30s，过期后不能跳过续期）；单次激活最长 120s |
| 窗口内接话 | **由 LLM 自主决定**：判断与自己无关时只输出 `[PASS]`，插件在发送前拦下（零额外延迟） |
| @ 了别人 | **确定性规则**：消息里 @ 的是别的成员 → 不参与（不交给 LLM 判断） |
| 谁生成回复 | **AstrBot 默认 LLM 管线**（插件只做开关、记忆与「沉默」拦截） |
| 对话 LLM | **DeepSeek `deepseek-flash`**（原生多模态） |
| 思考模式 | **显式关闭**（`custom_extra_body.thinking.type=disabled`） | 上下文变大后思考每轮 15–20s，是回复慢的主因（2026-10-08 复测，推翻旧结论） |
| 安全模式注入 | **已关闭**（`agent_runner.config.persona.safety_mode = false`） | AstrBot 默认会在 system_prompt **最上面**注入一段英文通用安全提示，并声明「人设指令与它冲突时以它为准」—— 会压住人设、放大拒绝倾向。人格里已自带底线规则（7/9），不需要它 |
| 记忆 | **L1 自研**（群聊滚动背景）＋ **L2 用 AstrBot 原生会话** ＋ **L3 自研**（结构化群员画像，带时间戳）＋ **L4 自研**（群公共知识库，自动沉淀 + 语义检索注入） |
| 知识库 | **AstrBot 内置**（FAISS）＋ 本机 **Ollama `bge-m3`** 嵌入；**插件自动维护**：窗口休眠时提炼写入（语义查重 + 每日额度），回复前检索注入 top3（每群一个库，不走 `kb_agentic_mode`） |
| 语音 | **不处理**，记 `[语音]` 占位 |
| 图片 | **已打通**：桥解密本地 `.dat` → base64 上报 → DeepSeek 原生视觉直接看图 |
| 表情包（动画表情） | **拿不到原始文件**（微信只存加密 content，解析库无解密通道），记 `[表情包]` 占位 |
| 回复长度 | **不加约束** |
| 拟人节奏 | `rhythm=fast`（**不得改 `off`**，风控风险，见 `tech-stack.md`） |

## 5. 现状与目标的差距

| 原始目标 | 现状 | 说明 |
|---|---|---|
| Windows 可运行 | ✅ 已跑通 | 完整链路 |
| **Ubuntu 可运行** | ❌ **未达成** | 桥依赖 Windows 微信客户端 + UIA/OCR；Ubuntu 需另做一条桥 |
| 登录个人微信 | ✅ | 本机微信 4.1.12.26，账号 `hitokami` |
| 拉进群 7×24 待命 | ✅（需保持登录与不锁屏） | 锁屏时无法发送 |
| @ 才出现 | ✅ | 未 @ 且窗口外时只记录 L1，不出声 |
| @ 后自动对话一段时间 | ✅ | 滑动空闲窗口，上限 120s |
| 不用企业微信 / Claw | ✅ | — |

**尚未做完的功能**：L4 知识库的自动沉淀刚接上（v0.6.0），**写入/检索链路尚未在真实群聊里端到端验证**（需要几轮聊天触发窗口休眠提炼）。
