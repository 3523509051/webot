# v0.21.0：可靠记忆、统一身份与 L20

实施日期：2026-11-14。部署及数据核验详见 [执行进度](memory-upgrade-progress.md)。

用户已决定由实机使用继续验收，停止后续自动测试及旧记录恢复工作；本说明只描述已上线主体，不包含未发布的恢复日志或额外并发审计实验。

## 行为变化

- L2 最近对话与完整原文分开：SQLite 保留原文；500 条是热视图，通常注入最近 200 条并限制 12000 字。
- 人物以 wxid 建立稳定身份，保留桥 ID、群内别名及来源。成员名单不再按昵称生成另一套用户 ID。
- 已确认的别名可查同一人的画像；同名和近似名字不自动合并。旧聊天只有在原始正文、时间和发送者证据不冲突时才回填身份。
- 已放行对话中的明确保存由程序提交并产生真实回执；支持多事项、修改、取消、相对日期。交代者和事项主体分别关联。
- 记忆保存成功而向量索引未完成时，原文仍可查询。索引待办会重试，并按固定文档名称避免重试新增重复文档。
- 回忆问题在主模型回答前查询身份、日期、原文、画像与语义知识；区分未命中、歧义、故障和部分查询。
- 后台分块整理话题，跨上海日期分开；总结保留来源，不删除原文。每日索引也覆盖消息少、尚未生成总结的日期。
- L20 记录工具真实结果、图片编号与已有文件名、文件版本/读取范围、查询和发送状态。关联到对应回复下方，仅进入模型历史，不追加到微信群回复。

## 使用示例

先按现有方式 @机器人，再提出请求：

```text
记住：下周三交初稿；另外，周五检查格式
我昨天让你记住什么？
把之前记住的改成周四交初稿
取消刚才记住的周四交初稿
Amy 是谁？
昨天群里聊了什么？
```

无法唯一确定待修改记录、保存内容或人物时会要求澄清，不猜一个写入。保存日期不等于安排定时提醒。

“图片返回过”只证明图片数据曾进入工具链；追问没保留的新细节时仍允许重读。文件读取记录标注版本和截断状态，目录查询不记为已经看过内容。

## 数据与开关

服务端新库：`C:/webot/data/astrbot/plugin_data/astrbot_plugin_group_activation/memory_store.sqlite3`。容器内对应 `/AstrBot/data/plugin_data/astrbot_plugin_group_activation/`。

`record_store_enable` 控制可靠记录；`record_store_read_enable` 控制新读取；`identity_enable`、`explicit_memory_enable`、`journal_enable`、`l20_record_enable`、`l20_inject_enable`、`memory_prelookup_enable` 分别控制对应功能。`memory_groups=[]` 表示对所有监听群启用新读取。

`memory_cleanup_enable=false` 保持原文物理清理关闭。旧 JSONL/L3 文件保留兼容及迁移来源。L4 是可重建索引，不是唯一依据；系统生成的 `[webot-memory:...]` 文档不会再作为旧资料重复导入。

## 清理与回退

- `/gaclear` 清 L1 与活动，不清原文。
- `/gareset` 隔离 L2 当前上下文及相关 L20；明确回忆查询仍可回查重置前原文。
- `/gaforget` 遗忘本群画像；`/gakbforget` 清本群知识索引，明确保存原文与画像按各自范围处理。
- 管理员 `/gamemorypurge confirm` 完整清本群新记忆、来源、日记和 L20，并清兼容文件与长期库。其他群不受影响。
- 回滚须保留并读取新库，不能仅替换成完全不了解新库的旧插件。不得用本机旧数据覆盖服务端新数据。

本次未改贝蒂联动。实际自然语言理解仍有边界：输入含糊时需明确事项；已无法取得来源的历史不能凭总结补造原话。
