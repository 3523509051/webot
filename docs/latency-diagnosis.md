# 回复延迟诊断报告

日期：2026-10-07　｜　现象：群里 @ 机器人后，回复要等 4–7 秒，期间微信界面出现「先搜索群聊」的动作

---

## 一、结论先行

延迟的**大头不在 LLM，也不在 AstrBot**，而在**桥驱动微信界面的发送链路**（拟人节奏层 + UI 会话切换）。

**决定性证据**：17:39:33 那条 `[M2] 收到：你好` 回复是插件写死的字符串，**全程没有调用任何 LLM**，却耗时 **6.57 秒**。

---

## 二、实测数据

### 1. DeepSeek API 直连测速（同一台机器、同一 key、同一模型 `deepseek-flash`）

| 请求参数 | 耗时 | 思考输出 | 输出 tokens |
|---|---|---|---|
| 默认 | 1.42s | 94 字符 | 67 |
| `thinking: {type: disabled}` | **1.12s** | **0** | **8** |
| `enable_thinking: false` | 1.17s | 134 字符 | 100 ← **此参数无效** |
| 默认（复测） | 1.23s | 109 字符 | 80 |

结论：
- 模型本身只要 **1.1–1.4 秒**，不是瓶颈。
- V4.1 Flash **默认开启思考模式**；关闭它的正确参数是 `thinking: {"type": "disabled"}`（`enable_thinking=false` 无效）。

### 2. 桥的 UI 探测耗时（只读实测）

| 动作 | 耗时 |
|---|---|
| `_get_uia()` | 0.44s（仅首次，之后缓存） |
| `uia.current_chat()` | 0.30s |
| `current_chat()` 返回值 | `'测试群'` |

**重要**：UIA 返回的当前会话名 `测试群` 与我们配置里传给 `send_msg` 的 `who` **完全一致** → 正常情况下 `open_chat` 会被跳过，**不会**每次都搜索群聊。

## 三、延迟构成拆解

以「回复 6.5 秒」为例：

| 环节 | 耗时 | 说明 |
|---|---|---|
| DeepSeek 调用 | ~1.2s | 已实测 |
| AstrBot 管线 + 插件注入 | <0.3s | L1 注入只是拼字符串 |
| **桥：UIA 探测** | ~0.3–0.8s | `current_chat()` 等 |
| **桥：逐字键入** | **1–2s+** | `rhythm.type_gap = 0.04–0.08s/字`，**回复越长越慢** |
| **桥：发送闸门** | **0.6–1.4s** | `rhythm.gate('send')` 强制最低间隔 |
| **桥：会话切换** | 1–3s | 仅当微信当前会话**不是**目标群时触发 |

---

## 四、「先搜索群聊」的确切来源

来自 `wechatauto/guia.py` 的 `open_chat()`：

```
send_msg() → uia.current_chat() == who ?
               ├─ 相等 → 跳过 open_chat（快）
               └─ 不等 → open_chat(who)
                            ├─ 侧栏 find_session 查找+点击（最多 3 轮，每轮 sleep 0.5）
                            └─ 最后手段 _search_chat() 走搜索框
```

即：**只有当「微信当前打开的会话不是目标群」时**，才会出现你看到的「搜索群聊」动作。若你当时正在看别的聊天窗口，机器人回复前必然会先切会话 —— 那 1–3 秒就是它。

## 五、可选优化与风险

| 方案 | 收益 | 风险 |
|---|---|---|
| **关思考模式**（Provider 的 `custom_extra_body` 设为 `{"thinking": {"type": "disabled"}}`） | 省 0.3s + 输出 token 从 ~70 降到 ~8 | **无风险**，推荐 |
| **让回复更短**（群聊人设限长） | 每少 10 个字省约 0.6s | 无风险 |
| `rhythm` 档位改 `off` | 省 1.5–3s（去掉逐字停顿与发送闸门） | ⚠️ **高**：`rhythm.py` 作者明确记载「2026-09-21 本机账号触发过一次风控」，`off` 仅供对照实验 |
| `rhythm` 改 `natural`/`calm` | 无（更慢） | 更安全 |
| AstrBot 开流式响应 | 反而更慢 | 桥按条发送，流式会变成多次 UI 发送 |

> **不建议**为了速度把 `rhythm` 设为 `off`：本项目登录的是真实个人号，且该账号已有一次风控记录。
