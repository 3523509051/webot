## 4. 验收标准（现状基线）

| 场景 | 期望 |
|---|---|
| 群里 @ 机器人 | 必须回复；**如果对方要求 @ 他，回复里带真实 @** |
| 窗口内（30s 滑动）普通消息 | 默认 LLM 处理；LLM 判断相关才接话，无关时 `[PASS]` 不发送 |
| 窗口内发图片 / 引用图片提问 | 模型能看到图（解密 + base64） |
| 模型想指名回某人 | 在回复里写 `@昵称`，桥转成真实 @ |
| 窗口外未 @ 的消息 | 不出声，但进入 L1 |
| 机器人自己发的消息 | 不被再次上报（无自问自答） |
| 微信锁屏时 | 发送失败（预期行为，非缺陷） |

## 5. 需要注意的红线

1. **`rhythm` 不得改为 `off`** —— 该账号已有风控记录（详见 `tech-stack.md` §6）。
2. **插件不要调 `event.send()` / `call_llm=True` / `stop_event()`** —— 会抑制或中断默认 LLM。
3. **不要开启 AstrBot 内置的群聊上下文与主动回复** —— 与插件重复且显著增延迟。
4. **改插件后必须确认挂载生效** —— 否则代码不生效（曾经因此长时间误判）。
5. **改 `scripts/*.ps1` 后要补 UTF-8 BOM**（跑 `scripts/fix-bom.ps1`）—— 否则 PowerShell 5.1 中文乱码。
